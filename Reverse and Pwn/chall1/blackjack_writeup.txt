IITCTF - BLACKJACK
===================

Category: Reverse Engineering
Difficulty: Easy

Flag:
IITCTF{h1tM3_w1th_Th3Fl4g}


CHALLENGE DESCRIPTION
---------------------

You managed to beat the dealer, but apparently Blackjack isn't enough.

Find the hidden winning hand and claim your prize.


INTENDED SOLUTION
-----------------

1. Run the binary
2. Perform basic reconnaissance with file and strings
3. Notice that getting 21 does not reveal the flag
4. Open the binary in Ghidra
5. Locate the hidden hand-validation logic
6. Recover the two mathematical conditions
7. Solve for the valid card combination
8. Enter the winning hand and obtain the flag


1. RUN THE BINARY
-----------------

Run:

    ./blackjack

The program asks for two card values:

    Enter your first card (1-13):
    Enter your second card (1-13):

Try a normal Blackjack combination:

    10
    11

The program reports:

    Your hand: 10 + 11
    Your score: 21
    Dealer's score: 20

    BLACKJACK!
    But something seems to be missing...

This is an important clue.

The player has achieved 21, but the flag was not revealed. Therefore,
there must be another hidden condition in the program.


2. BASIC RECONNAISSANCE
-----------------------

Check the binary type:

    file blackjack

The binary is an ELF executable.

Next, inspect printable strings:

    strings blackjack

Useful strings such as the following can be found:

    BLACKJACK
    Dealer's visible card:
    Enter your first card (1-13):
    Enter your second card (1-13):
    BLACKJACK!
    But something seems to be missing...
    Congratulations!
    You found the hidden winning hand!

The flag itself is not directly visible because it is XOR-encoded
inside the binary.

At this point, static reverse engineering is the intended next step.


3. OPEN THE BINARY IN GHIDRA
----------------------------

Import the binary into Ghidra and allow Ghidra to perform auto-analysis.

Open the Functions window.

The important functions include:

    main
    calculate_score
    hidden_check
    print_flag

Start by examining main().

The relevant program flow is approximately:

    card1 = user input
    card2 = user input
    score = calculate_score(card1, card2)

    if (hidden_check(card1, card2))
        print_flag()


4. ANALYZE hidden_check()
-------------------------

Opening hidden_check() reveals the important logic:

    if (card1 + card2 != 21)
        return 0;

    if ((card1 + 4) * (card2 - 5) == 96)
        return 1;

    return 0;


This means that there are TWO conditions that must be satisfied.

Getting a score of 21 is necessary, but it is NOT sufficient.


5. FIRST CONDITION - SCORE 21
-----------------------------

The first condition is:

    card1 + card2 = 21

There are multiple possible combinations within the allowed card range.

For example:

    8 + 13 = 21
    9 + 12 = 21
    10 + 11 = 21

This explains why entering 10 and 11 results in Blackjack but does
not reveal the flag.

There is another hidden condition.


6. SECOND CONDITION - HIDDEN EQUATION
-------------------------------------

The second condition is:

    (card1 + 4) * (card2 - 5) = 96

We now need a pair of card values that satisfies BOTH equations:

    card1 + card2 = 21

and:

    (card1 + 4) * (card2 - 5) = 96


7. VALID CARD RANGE
-------------------

The program also checks that both cards are valid:

    if (card1 < 1 || card1 > 13 ||
        card2 < 1 || card2 > 13)
    {
        printf("Invalid card value!");
        return 1;
    }

Therefore:

    1 <= card1 <= 13
    1 <= card2 <= 13

We only need to search within this small range.


8. SOLVE THE CONDITIONS
-----------------------

Try card1 = 8 and card2 = 13.

First condition:

    8 + 13 = 21

So the hand has Blackjack.

Now check the hidden equation:

    (8 + 4) * (13 - 5)

    = 12 * 8

    = 96

Both conditions are satisfied.

Therefore:

    card1 = 8
    card2 = 13

is the hidden winning hand.


9. OPTIONAL BRUTE FORCE
-----------------------

Because the search space is only 13 x 13, the solution can also be
found with a short Python script:

    for card1 in range(1, 14):
        for card2 in range(1, 14):
            if card1 + card2 == 21:
                if (card1 + 4) * (card2 - 5) == 96:
                    print(card1, card2)

Output:

    8 13


10. GET THE FLAG
----------------

Run the binary again:

    ./blackjack

Enter:

    Enter your first card (1-13): 8
    Enter your second card (1-13): 13

The program satisfies both hidden conditions and prints:

    IITCTF{h1tM3_w1th_Th3Fl4g}

KEY LEARNING POINTS
-------------------

- Identify an ELF executable with file.
- Perform initial reconnaissance with strings.
- Recognize when strings is not enough.
- Import and analyze a binary with Ghidra.
- Locate main() and follow function calls.
- Read simple decompiled C-like logic.
- Recognize that a visible condition may not be the complete
  validation logic.
- Recover the intended input from a hidden check.
- Use a small brute-force script when the search space is limited.


AUTHOR NOTES
------------

This is intended as a beginner-friendly reverse engineering challenge.

The challenge intentionally avoids:

- Packing
- Anti-debugging
- Complex cryptography
- Buffer overflows
- Complicated assembly
- Randomness affecting the solution
- Obfuscated control flow

The main lesson is:

    "Getting Blackjack is not enough.
     Reverse the program to find the hidden winning hand."

The flag is XOR-encoded with key 0x5A in the binary so that it does not
appear directly in a simple strings search.
